Introduction

Moonframe is a factory for native desktop apps whose whole window is written in Luau. Rust checks its element trees; GPUI draws them by default, with Rune as an experimental alternative. Both use the same Luau: every panel, split, toolbar and status bar is a file that reloads as you save, with its state kept.

$ git clone https://github.com/moonframehq/moonframe my-app
$ cd my-app
$ mise install   # Rust, and Zig for the Ghostty terminal
$ just run       # opens the window on app/

GPUI is the default in installed apps and published releases. To try Rune from source, use just rune, just rune-gallery or just rune-app NAME. Rune supports profiles, providers and live reload, but layouts can differ and features such as named themes, animations and separate mod windows are still missing. See the Rune screenshots and backend guide.

Quick start →Clone, run, edit a file, watch it change. Your first mod →State, init, update, view. Component catalogue →Every ui.* element and use piece. Build an app →moonframe.toml, profiles, bundles.

A mod is one file

The shell, app/main.luau, places regions, and mods fill them. Each mod has its own state, init, update and view, like an Elm program; mods talk with messages.

-- app/mods/counter/main.luau
return mod {
	region = "left",
	init = function(previous)
		return previous or { count = 0 }
	end,
	update = function(state, msg)
		if msg == "add" then state.count += 1 end
	end,
	view = function(state, app)
		return ui.panel { title = "Counter",
			ui.text(`Clicked {state.count} times`),
			ui.button { "Add", msg = "add", variant = "primary" } }
	end,
}

Save it and it appears in the left region.

A new kind of elementRust in crates/, the one change that needs a rebuild
SandboxedLuau runs with no files, network or process access, a memory cap and an instruction budget. Anything that reaches the machine goes through a provider or an element the host owns. A WebAssembly (WASM) provider is sandboxed the same way and reaches only the host calls its manifest lists; process and native providers run as you, for what a sandbox cannot reach. What runs with what access

Build a WebAssembly (WASM) provider → A complete Rust component, a Luau view, messages, live reload and packaging, for people and coding agents.

For coding agents

Ask your agent to “use Moonframe for this project: read https://moonframe.dev/llms.txt and follow it.” llms.txt walks it through the choice: an existing Rust crate gets the library with moonframe init; a new app with no Rust of its own, or a UI for a project in another language, becomes a profile with moonframe app new. It then points at the skills to read before writing UI, and at --check to run after each edit.

Platforms

Moonframe is developed on macOS. CI builds, lints and tests it on macOS, Linux (x86_64 and ARM64) and Windows; each release ships a macOS disk image, Linux tarballs and Windows zips, with checksums, Sigstore signatures and GitHub attestations.
